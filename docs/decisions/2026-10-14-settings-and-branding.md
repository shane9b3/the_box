# Settings additions and branding (owner request, 2026-10-14)

Owner asked, after M2 closed, for settings covering: tunneled playback, MPEG-TS vs HLS, audio passthrough, removing channel-name prefixes, hiding and showing channels and sections (groups), switching sections easily, and remote button mapping for every kind of control. The owner also supplied the logo.

Status of each against the approved settings tree (`docs/review/product-review.md` §4) and the M2 contracts. **Existing** means the row is already in the tree and the engine honours it; the screen that exposes it ships in M5. **New** means scope is added here; the design gets a proposer and a reviewer in the milestone that builds it, as the working agreement requires.

| Request | Status | Where it lives | Decision |
|---|---|---|---|
| Tunneled playback | Existing | §4.4 "Tunneled playback" toggle, default Off, advanced; `PlaybackSettings.tunneling` (M2) | Keep. Default stays Off (black screens on several chipsets). Changing it is a runtime track-selector switch, no player rebuild. |
| MPEG-TS or HLS | Existing | §4.2 "Stream format (Xtream)" Auto / TS / HLS per playlist; `PlaylistPlaybackInfo.xtreamOutput` + `xtream_output_learned` (M2) | Keep. Auto = TS, flips to HLS on 405/406 and remembers. Label in the UI: "Stream format: Auto / MPEG-TS / HLS". Direct M3U URLs are whatever the entry says; the row is hidden for non-Xtream playlists. |
| Audio passthrough | Existing, **one option added** | §4.4 "Audio output" Auto / Always decode (PCM) / Stereo; `PlaybackSettings.audioOutput` | Add **Always passthrough**: send AC-3/E-AC-3/DTS/TrueHD to the sink even when the HDMI caps do not list them (Fire TV and some AVR chains misreport). The 3 s silence watchdog still drops to PCM, with a toast naming the reason. Engine: `AudioOutputMode.FORCE_PASSTHROUGH`, gate ignores `AudioCapabilities` for the listed encodings; M2 `PassthroughGateAudioSink` already has the denial path. Build with M5, tested on the emulator's PCM-only sink. |
| Remove channel prefix | **New** | Per-playlist, §4.2: "Channel name prefix: Auto / Off / Custom", default **Auto** | Display name only; the stable key and matcher input are unchanged. Auto strips a leading country or group tag of the forms `UK: `, `UK | `, `UK - `, `[UK] `, `(UK) `, `UK\|` when the tag is an ISO-3166 code or `UK`, or equals the entry's group name, case-insensitively. Custom = list of literal prefixes or a regex with a live preview count. Data: `channel.display_name` computed in the M1 merge from the rule, recomputed on rule change without a re-import (one UPDATE pass). Guide, info bar, channel list and search all read `display_name`. M3 builds it (the guide is the first consumer). |
| Hide / show channels and sections | Existing | §4.5 groups show/hide/lock/reorder, hidden-channels list, keyword hide rules; long-press OK → Hide channel (§2.3); groups review at onboarding (S6) | Keep. Add one shortcut: long-press OK on a group in the Groups panel offers Hide / Lock / Move, already in S7a. |
| Switch sections easily | Existing, **two accelerators added** | Group chip in the guide header; Groups panel (S7a) one Up press from the top row, also Green; player ← opens the channel list with the group column focused | Add: **Left at the channel column edge** (first programme cell at the archive limit) opens the Groups panel, the TiviMate gesture, no longer conditional on the parity session. Add: **CH+ / CH− while the Groups panel is open** moves to the next/previous group and reloads the grid, and **long-press ← / →** in the player cycles groups (card shows the group name). "Open guide on" (All / Favourites / Last group) stays. |
| Remote button mapping | **Pulled forward from v1.1 to v1** | §4.7 Remote control gains a **Button mapping** screen (M5) | Every app action is listed and each key can carry a short-press and a long-press action. Actions: zap up/down, previous channel, guide, channel list, groups panel, quick menu, audio, subtitles, aspect, start over, favourites, info bar, number entry, play/pause, seek back/forward, jump to live, stats overlay, screen off, exit. Capture is "Press a key now" on a `KeyEvent` listener, showing the key name and the source device (`InputDevice.name`), so D-pad-only remotes, Fire TV, TV-maker remotes with numbers/colour/CH±, HDMI-CEC remotes, keyboards and game controllers all work the same way. Reserved: D-pad and OK keep navigation outside the player, Back keeps "close top layer", Home is OS-owned. Conflicts are shown inline and the later binding wins. Reset to defaults per key and globally. Per-device profiles stay v1.1. |

## Branding

The owner's logo is in `design/logo/The_Box.png` (1,158 × 480, black wordmark "The Box" on white, rounded-box frame). Derived assets to produce in M3 together with the first real screens, each committed under `app/src/main/res`:

- Android TV banner 320 × 180 dp (`xhdpi` 640 × 360 px): wordmark inverted to white on the base `#0A0D13`, 24 dp padding, no gradient.
- Adaptive launcher icon: foreground = the box frame with "Box" only (the "The" does not survive 48 dp), background = `#0A0D13`.
- In-app wordmark (guide header, about screen): white on dark at the design scale; monochrome SVG traced from the PNG so it scales with the 1 design px rule.
- Keep the black-on-white original for store listings and the phone-assisted setup page.

The wordmark's rounded-box frame is also the natural shape for the focused-cell outline and the channel-number chip; `docs/01-design-reference.md` already uses rounded rectangles, so no token change is needed.
