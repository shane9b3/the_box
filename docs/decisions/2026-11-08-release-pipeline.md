# 2026-11-08: Release pipeline (M5 §8 Q7/Q8 resolved)

**Owner decisions.** Releases are published on the public GitHub repo `shane9b3/the_box`. They are built and signed on
the owner's Mac by a script, not in CI. The release keystore and both Ed25519 manifest keys were generated by the lead
and live in `~/.thebox-release/` (never in git; the owner backs it up offline).

**What was built.**
- `ReleaseUpdateConfig.UPDATE_REPO = "shane9b3/the_box"`, `UPDATE_PUBLIC_KEYS_HEX = [current, next]`. The release
  updater is on. §3.12.1 named a `BuildConfig.UPDATE_REPO`; the existing plain constant is kept (one source of truth
  that the release script parses to check URLs and keys). The debug build still trusts only its test key.
- `version.properties` (versionCode, versionName) read by `app/build.gradle.kts`, overridable with
  `-Pthebox.versionCode/-Pthebox.versionName`.
- `tools/release/release.py` (stdlib, `python3 -I`): preflight, bump, `:app:assembleRelease`, aapt2 + apksigner checks
  against the release certificate, `update.json` + OpenSSL Ed25519 `update.json.sig`, verification against the keys
  parsed from the Kotlin source and the last tag's keys, commit/tag/push, draft release → assets → publish, public
  re-fetch through the app's redirect allowlist. `--dry-run` writes only `build/release/`.
- Manifest `sequence` = versionCode: strictly increasing by construction (the script refuses a code not above every tag
  and the live manifest), clock-free and reproducible. Consequence: a published manifest is never re-signed for the same
  versionCode; fixes are N+1 (as §3.12.5 already says).
- APK assets are named without the version (`TheBox-universal.apk` etc.) so `releases/latest/download/TheBox-universal.apk`
  is a permanent sideload link.
- Cross-check: `tools/release/test_release.py` produces a fixture signed with a throwaway key;
  `data/.../ReleaseManifestFixtureTest` runs it through the real `ManifestVerifier` + Tink.

**Measured.** `github.com/<o>/<r>/releases/latest/download/<asset>` → `github.com/…/releases/download/<tag>/<asset>` →
`release-assets.githubusercontent.com` (2026-11-08); all hosts are in `UpdateTimings.REDIRECT_HOSTS` (closes §9 F13).
