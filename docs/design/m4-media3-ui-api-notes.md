## 2. Seeking on finite HTTP TS and HLS VOD

### 2.1 Does a finite `.ts` seek natively?

- **Fact** — `TsExtractor` is seekable only if it could read a duration: in `read()`, once tracks ended and `input.getLength() != C.LENGTH_UNSET` and mode is not HLS, it runs `TsDurationReader.readDuration`; afterwards `maybeOutputSeekMap`: duration known → `TsBinarySearchSeeker.getSeekMap()` (a `BinarySearchSeekMap`, `isSeekable() == true`); else `SeekMap.Unseekable(durationReader.getDurationUs())`. — `media:extractor/ts/TsExtractor.java:426-436,:540-555`; `BinarySearchSeeker.java:518-520`; `SeekMap.java:31`.
- **Fact** — `TsDurationReader` needs a PCR PID. It reads the **last** PCR (seeks near the end), then the **first** PCR (seeks to 0), each by peeking `timestampSearchBytes` = **`DEFAULT_TIMESTAMP_SEARCH_BYTES = 600 × 188 = 112,800` bytes**; `duration = adjustedLastPcr − adjustedFirstPcr`, handling one PCR wrap. If either PCR is not found, duration stays `TIME_UNSET` and the seek map is unseekable. — `TsDurationReader.java:82-105,:131-165`; `TsExtractor.java:124`.
- **Fact** — Each `RESULT_SEEK` from the extractor makes `ProgressiveMediaPeriod`'s loader **close the data source and reopen it at the requested byte position** (`DataSourceUtil.closeQuietly(dataSource)` in the `finally`, next `dataSource.open(buildDataSpec(position,…))`). So preparing a finite TS costs about three opens: from 0, tail (`length − 112,800`), head again, then continue. — `media:exoplayer/source/ProgressiveMediaPeriod.java:1304,:1346-1352`. **[inference]** on the count.
- **Fact** — `TsBinarySearchSeeker`: `SEEK_TOLERANCE_US = 100,000`, `MINIMUM_SEARCH_RANGE_BYTES = 5 × 188`; seek targets are PCR times; it is time-to-byte by binary search, not keyframe-aware. — `TsBinarySearchSeeker.java:38-39`. Then `TsExtractor.seek` resets payload readers and `tsPacketBuffer` (`:384-420`); `checkState(mode != MODE_HLS)` (:385).
- **Fact** — `ProgressiveMediaPeriod` marks the stream **live** when `!isLengthKnown && seekMap.getDurationUs() == TIME_UNSET` (`:970`); `isLengthKnown` is set when `dataSource.open` returns a length ≠ `LENGTH_UNSET` (`:1304-1307`). `ProgressiveMediaSource` builds `SinglePeriodTimeline(durationUs, isSeekable = seekMap.isSeekable(), isDynamic = false, useLiveConfiguration = isLive, …)`. — `ProgressiveMediaSource.java:481-492,:505-513`. A seek into a non-seekable map is treated as a seek to 0 (`ProgressiveMediaPeriod.java:589-590`).
- **Fact** — Result for the UI: **a finite TS with `Content-Length` and PCRs gives `isCurrentMediaItemSeekable == true` and a real `getDuration()`; a live-shifted or chunked TS gives `isLive`, `isSeekable == false`, `getDuration() == TIME_UNSET`, and `COMMAND_SEEK_IN_CURRENT_MEDIA_ITEM` unavailable.** **[inference]** from the three bullets above plus `Util.getAvailableCommands` (below).
- **Fact** — `Util.getAvailableCommands` adds `COMMAND_SEEK_IN_CURRENT_MEDIA_ITEM`, `COMMAND_SEEK_BACK` and `COMMAND_SEEK_FORWARD` iff `isCurrentMediaItemSeekable && !isPlayingAd`; `COMMAND_SEEK_TO_NEXT/PREVIOUS_MEDIA_ITEM` need a next/previous item; `COMMAND_SEEK_TO_PREVIOUS` also needs `hasPrevious || !isLive || isSeekable`. — `media:common/util/Util.java:4108-4132`.
- **Fact** — Defaults: seek back 5 s, forward 15 s, max seek-to-previous 3 s (`C.java:1129,:1132,:1138`). The repo overrides both increments to **30,000 ms** (`PlayerFactory.kt:83-84,:113`). `seekBack()`/`seekForward()` call `seekToOffset(±increment, COMMAND_SEEK_*)`. — `BasePlayer.java:140-147`.
- **Fact** — `SeekParameters.DEFAULT == EXACT` (decode from the previous keyframe and drop to the target); `CLOSEST_SYNC`, `PREVIOUS_SYNC`, `NEXT_SYNC` exist. `ExoPlayer#setSeekParameters(SeekParameters?)`. — `media:exoplayer/SeekParameters.java:43-56`; `ExoPlayer.java:1900`.
- **Fact** — **Scrubbing mode exists in 1.11.1**: `ExoPlayer#setScrubbingModeEnabled(boolean)` / `isScrubbingModeEnabled()` / `setScrubbingModeParameters` / `getScrubbingModeParameters`. "The player may consume more resources… only for short periods… During scrubbing mode playback is suppressed with `PLAYBACK_SUPPRESSION_REASON_SCRUBBING`." — `ExoPlayer.java:1747-1768`. Not read in depth, and not reachable through `surfacePlayer`.
- **Repo** — **M4 cannot assume `.ts` archives are seekable from `nativeSeekRange`**: the builder returns null for `xc-path` with `ext = ts` although such files may be served with `Content-Length` and 206 (`CatchupUrlBuilderImpl.kt:129`; `docs/design/m2-playback-core.md:1933`). The authoritative gate is `PositionSnapshot.isSeekable = archive != null && player.isCurrentMediaItemSeekable` (`PlaybackControllerImpl.kt:1670-1680`, field at :1678). `durationMs` is `p.duration` or null when `TIME_UNSET` (`:1677`). `bufferedMs` is `totalBufferedDuration`, a **duration ahead of the playhead, not a position** (`:1676`).
- **Repo** — Back buffer is **0 for archive too** (`AdaptiveLoadControl.kt:52,:88`: `getBackBufferDurationUs = 0`, `retainBackBufferFromKeyframe = true`), so any backward seek beyond the retained keyframe is a new ranged open, not a buffer hit; forward seeks inside already-buffered data are resolved from the buffer. **[inference]** `ProgressiveMediaPeriod` seeks inside the buffer when it can (`seekInsideBufferUs`), otherwise reopens.
- **Repo** — Archive `ProgressiveMediaSource` uses the session placeholder URI and `SessionUriDataSource` swaps in the real URL while keeping `position`/`length`, so Range seeks work; `getResponseHeaders()` is empty (`MediaSourceBuilder.kt:78-85,:173-209`). The transport is `BrokeredHttpDataSource` over `OkHttpDataSource`: one lease per session, "Range allowed, no reconnect" (`StreamHttpDataSourceFactory.kt:22-33,:73-112`). Each reopen is a new OkHttp call under the same lease.

### 2.2 HTTP Range behaviour

- **Fact** — `HttpUtil.buildRangeRequestHeader(position, length)` returns null for `(0, UNSET)`, else `bytes=<pos>-` or `bytes=<pos>-<pos+len-1>`. — `media:datasource/HttpUtil.java:57-69`.
- **Fact** — If the server answers **200** to a ranged request, both `DefaultHttpDataSource` and `OkHttpDataSource` set `bytesToSkip = dataSpec.position` and read-and-discard that many bytes (then report `contentLength − bytesToSkip`); a **416** whose range is satisfiable at the end of the resource returns 0 length, otherwise throws `InvalidResponseCodeException`. — `DefaultHttpDataSource.java:379-403,:417-457`; `media:datasource_okhttp/OkHttpDataSource.java:285-308,:323-346`.
- **Fact** — `OkHttpDataSource` adds `Accept-Encoding: identity` (`:411`); `DefaultHttpDataSource` sends `gzip` only with `FLAG_ALLOW_GZIP` (`:521,:635`). `HttpDataSource.RequestProperties`: `set(name, value)`, `set(Map)`, `clearAndSet(Map)`, `clear`, `getSnapshot`. — `datasource/HttpDataSource.java:78-111`.
- **Repo** — user headers named `Range`, `Accept-Encoding`, `Host`, `Connection`, `Icy-MetaData` are dropped (`docs/design/m2-playback-core.md:1479`).

### 2.3 Player position, duration, buffering

- **Fact** — `getDuration()` "or `TIME_UNSET` if the duration is not known" (`Player.java:3114-3120`); `getBufferedPosition()` = position up to which data is buffered (:3138); `getTotalBufferedDuration()` = buffered duration **from the current position**, including pre-buffered items (:3148-3154); `isCurrentMediaItemLive()` :3190; `getCurrentLiveOffset()` returns `TIME_UNSET` unless the item is live and the offset is known, "may rely on an accurate local time" (:3194-3206); `isCurrentMediaItemSeekable()` = `timeline.getWindow(...).isSeekable` (:3224; `BasePlayer.java:387-390`). All need `COMMAND_GET_CURRENT_MEDIA_ITEM`.
- **Fact** — `getCurrentLiveOffset()` is `currentTime − playbackPosition` using `windowStartTimeMs`, `TIME_UNSET` when the window has no start time (so raw TS: always `TIME_UNSET`). — `BasePlayer.java:363-375`.

## 6. Catch-up URL variants and seekability

Sources: `core/src/main/kotlin/app/thebox/core/catchup/CatchupContracts.kt`, `CatchupUrlBuilderImpl.kt`, `FlussonicUrl.kt`, `TemplateExpander.kt`; `core/.../model/TimeBase.kt`; `core/.../xtream/XtreamUrls.kt`; `docs/research/protocols-m3u-xmltv-xtream.md` §3.3, §4; `docs/design/m1-data-layer.md` §3.8.5 (:2873-2885).

- **Fact** — Times in the builder: `S = archiveStart(programmeStart)` = `programmeStart − correction − paddingBefore`; `E = archiveStop(stop)` = `stop − correction + paddingAfter`; open-ended: `E = N`; `N = deviceNow + clockSkew`; `D = E − S`. **Correction is subtracted** (`TimeBase.kt:58-63`; `CatchupUrlBuilderImpl.kt:12-18,:52-65`; research :347). Defaults `paddingBeforeSec = 60`, `paddingAfterSec = 300` (`CatchupContracts.kt:49-50`). The depth check ignores padding; if only padding crosses the archive edge, `S = windowStart + 60 s` (`EDGE_MARGIN_SEC`, builder :164, :62-63). A programme not yet started → `Unsupported("the programme has not started yet")` (:55).
- **Fact** — Open-ended xc request: `D = min(N − S, MAX_OPEN_XC_SEC = 180 × 60)` (builder :68, :165). No cap is applied to a closed request; the research does not state a panel maximum for `duration`. **[unverified]** whether panels cap it.
- **Fact** — `ArchiveRequest.nativeSeekRange` is in **epoch seconds** (`CatchupContracts.kt:106`); the native seek window in player ms is `(epochSec − requestStart.epochSecond) × 1000` (`docs/design/m2-playback-core.md:1933`). `requestStart = S`, `requestEnd = E` (null if open). Position → wall clock: `requestStart + position`.

## 7. Fake panel today (`tools/fakepanel/fakepanel.py`)

- **Fact** — Endpoints that serve archive (all go through `stream_request("timeshift", …)`): `GET /timeshift/{u}/{p}/{minutes}/{start}/{id}[.ext]` (:672-674); `GET /streaming/timeshift.php?username&password&stream&start&duration` (:642-645, ext fixed `ts`); Flussonic-style `GET /live/{u}/{p}/{id}/{archive|index|video|mono}-{FROM}-{DURATION|now}.{m3u8|ts}` (:659-664, `start = "@" + FROM`); SHIFT `GET /live/{u}/{p}/{id}.ts?utc=…` (:666-670, `dur=None`). `timeshift_abs-…` and `timeshift_rel-…` paths are **not** routed (they fall to `404 not found`, :678). README `Timeshift` :90-97.
- **Fact** — Response for a `.ts` archive: the 10 s `std` clip repeated ×3 (`clip.data * 3`, :968) = **30 s file**, via `finite(…, ranges = cfg["timeshift_ranges"])` (:971). `finite()` (:983-1015): with ranges on it honours `Range: bytes=a-b`, `bytes=a-`, `bytes=-n` → **206** with `Content-Range`, **416** with `Content-Range: bytes */N` when `start >= N`, always sends `Accept-Ranges: bytes` and `Content-Length`. With `timeshift_ranges:false` it sends neither header and ignores `Range` (200, close-delimited, no length). Default `timeshift_ranges = True` (:46).
- **Fact** — `.m3u8` archive: a **VOD** playlist (`#EXT-X-PLAYLIST-TYPE:VOD`, `#EXT-X-ENDLIST`) listing the clip's 2 s segments once = **10 s**, segment URLs `/vodseg/{sid}_{n}.ts` (:1116-1123, :652-655). No `EVENT` type, no growing window.
- **Fact** — Request parameters the panel ignores: the `duration`/`{minutes}` value is passed to `timeshift_check` but never used to size the response; the response is the same 30 s / 10 s regardless of start or duration. (:936-939, :968)
- **Fact** — Validation (`timeshift_check`, :828-870): unparseable start → 404 `timeshift_bad_start`. A start in the future, or older than `archive_days*86400 + 3600`, or not matching `timeshift_expect` (±90 s) only **logs a WARNING and counts `timeshift_tz_warnings`**; the response is **404 only if `strict_timeshift_tz` is set**. The "older than the window" branch is an `elif` after the `timeshift_expect` branch, so it is skipped whenever `timeshift_expect` is set (:842-861).
- **Fact** — Faults (`FAULT_DOC` :53-57, README :76-86, per stream via `--stream-fault ID:KEY=JSON` or `/admin/config`): `linger` + `linger_status` (a closed connection keeps its slot for N s; a refused open answers `linger_status`: 403 default, **458, 509, 503**, any int, or `"close"` = 200 headers then close; :946-955), `stall`, `slow` (throttles `finite()`), `redirect` + `token_ttl` (302 to the LB port, :903-912), `ua_whitelist` (403), `wrong_content_type`, `html_splash` (200 HTML, :914-917), `405_on_m3u8`, `close_every`. Auth: `auth_mode` 401/403/513, `status` Expired/Banned/Disabled → 403. `range_rejects` (400/416) applies **only to live `.ts`** (:923-933).
- **Fact** — Connections: HTTP/1.0 close-delimited, **no keep-alive** (README :143), so each ranged reopen is a new TCP connection; `max_connections` slots are acquired per stream request and released in `finally` (:946,:975-976), `max_connections` default 2 (:41).
- **Fact** — Timestamps: "Timestamps are only rewritten for live TS. VOD, timeshift and archive TS are served unmodified" (README :139). `/admin/stats` exposes `request_log` (path, ua, token_present, end_reason; last 200), `range_requests_seen`, `stream_requests`, `connections` (README :108).
- **Gaps for a scrub-bar / probe instrumented suite:**
  1. **Looped timestamps** **[inference]**: the 30 s `.ts` is three byte-identical copies of a 10 s clip with identical PTS/PCR, so `TsDurationReader` (last PCR − first PCR) would see ≈ 10 s for a 30 s file and the PCR binary search is ambiguous. A test of "duration / seek lands where it should" needs a single 30+ s clip or continuous timestamps in the timeshift path (the live path already has the rewriter, README :128-134).
  2. **`duration` not honoured**: cannot test minutes-vs-seconds, `⌈D/60⌉`, padding, programme end, or "stream ends at the requested duration".
  3. **No `404` on out-of-archive by default**; only under `strict_timeshift_tz`, and not combinable with `timeshift_expect` for the window check. Needs a mode that returns 404/403 for starts older than the channel's archive days and for starts in the future.
  4. **458/509 on seek**: no fault that rejects a **ranged** timeshift request or a second concurrent open mid-playback (TiviMate audit :142 reports 458 on every FF/RW). `linger` rejects only the open that arrives during the linger window; combined with `max_connections=1`, the extractor's tail-read reopen during prepare would be refused. **[inference]** `range_rejects` should be extended to timeshift.
  5. **No live-shifted archive**: SHIFT and Flussonic `-now`/`timeshift_abs` return the same finite file, so the "unseekable archive" path (no Content-Length, `isLive`, `COMMAND_SEEK_*` unavailable) is only reachable via `timeshift_ranges:false` (no length at all). No "Content-Length present but Range ignored (200)" mode, which exercises the `bytesToSkip` path (§2.2).
  6. **No HLS EVENT/live-window or discontinuity archive playlists**, no per-segment tokens on `/vodseg/`.
  7. **Out-of-routes**: `timeshift_abs-{S}.{ts,m3u8}`, `timeshift_rel-{N}.m3u8`, `…-now.m3u8` (Flussonic "open" forms the builder emits) return `404 not found`.
  8. **EPG/archive alignment**: `has_archive` and the window are fixed at server start (README :69), so tests near the archive edge drift.
